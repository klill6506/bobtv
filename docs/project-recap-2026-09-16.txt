BobTV + Whole-Home Control Project
Big Picture
The goal is no longer just “watch BBC on a little Linux PC.”
The larger idea is to turn the MeLE mini-PC into a Bob-powered home entertainment and smart-home hub.
At a high level:
You / household
      ↓
Voice / remote / BobTV screen / phones
      ↓
BobTV + Bob
      ↓

│ Entertainment               │

│ future Canada/Australia     │
│ What'sOn / Trakt            │
└─────────────────────────────┘
      ↓
┌─────────────────────────────┐

│ Hue                         │
│ Alexa / Google / Apple      │
│ smart plugs                 │

The long-term objective is that nobody in the house needs to know there is a Linux computer behind the TV.
Ideally the experience becomes:
“Bob, put BBC One on.”

or press one button on the remote.
BobTV handles the VPN, streaming service, TV input, audio, lights, etc.

BobTV Software
This is one of the most important things we've accomplished.
Codex created an actual reusable BobTV command layer rather than a BBC-specific script.
Main command:
bobtv
BBC invocation:
bobtv launch bbc-iplayer
Explicit path:
/home/ken/.local/bin/bobtv launch bbc-iplayer
Architecture:
~/.local/bin/bobtv
        ↓
Projects/bobtv/bobtv.py
        ↓
Projects/bobtv/services.json
services.json
Contains service definitions rather than hard-coded Python logic.
BBC example:
"bbc-iplayer": {
  "name": "BBC iPlayer",
  "region": "uk",
  "url": "https://www.bbc.co.uk/iplayer"
}
When BobTV launches BBC:
1. Determines required region.
2. Checks NordVPN status.
3. Reuses a UK connection if already connected.
4. Otherwise connects Nord to United Kingdom.
5. Verifies the VPN actually reports UK.
6. Opens BBC iPlayer in Chromium.
7. Refuses to open the browser if VPN verification fails.
This is exactly the architecture we want.

Disk Encryption
The SSD uses:
LUKS disk encryption
That currently means the machine may require a password after a full reboot/power loss.
We deliberately decided not to change that yet.
Eventually we could consider TPM-backed automatic disk unlock, but that's not necessary for the current phase.
For now:
power outage
   ↓

   ↓
Omarchy auto-login
   ↓
BobTV ready
That's acceptable for now.

Future Hardware Projects
BobTV is also our introduction to hardware programming.
We discussed:
Raspberry Pi
Small general-purpose Linux computer.
ESP32
Very inexpensive Wi-Fi/Bluetooth microcontroller for sensors, relays, buttons, IR transmitters, etc.
Future possibilities:
- custom sensors
- infrared controllers
- smart buttons
- physical status displays
- scanning appliances
- office hardware automation
- custom Delvio hardware
- improved scanner workflows
- eventually custom circuit boards
Important design constraint:
Avoid tiny/fiddly electronics whenever possible.
We'll favor:
- pre-soldered modules
- larger development boards
- screw terminals
- Grove-style connectors
- USB
- ready-made enclosures
- spending a little extra for easier hardware
No microscopic soldering unless absolutely necessary.
Design Principles
These are worth preserving for the entire project.
1. Appliance, not computer
The household should not need Linux knowledge.
2. One action layer
All interfaces should call the same BobTV actions:
remote
voice
home screen
phone
automation
      ↓
bobtv command
3. Configuration over hard coding
Adding a service should ideally mean changing services.json, not rewriting BobTV.
4. AI manages complexity
Ken decides what the machine should do.
Codex handles much of the Linux/configuration detail.
5. Don't replace working systems without a reason
Trakt and What'sOn already solve real problems.
Home Assistant already solves smart-device integration.
Use them where appropriate.
6. Build incrementally
BBC first.
Then remote.
Then CEC.
Then interface.
Then smart home.
Then recommendations/profiles.
Don't attempt the entire Jarvis house at once.
